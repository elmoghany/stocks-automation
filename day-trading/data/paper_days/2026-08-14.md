## Ops: a blocking tooling bug, found and fixed at 07:19

`day-trading.py rank` died mid-cycle:

```
File "day-trading.py", line 282, in __init__
    (2 * (self.c - self.l) - rng) / rng, 0.0)
ZeroDivisionError: float division by zero
```

**Root cause.** A day whose bars are *all interpolated* leaves a **header-only CSV** in
`data/rh_bars` — `DAAQ_2026-08-13.csv`, written by Day 8's own fake-gap names. `load_rh_bars`
does `pd.concat` across every cached file for a symbol, and concatenating that empty,
object-dtype frame with a real one silently coerces **every OHLCV column to `object`**.
`Candles.__init__` guards flat bars with `np.where(rng > 0, ...)` — but on an object array numpy
evaluates both branches in plain Python, so a bar with `high == low` **raises** instead of being
masked.

**Why it matters.** Flat 1-min bars are the norm on illiquid gappers — 5 of today's 10 candidates
carry them. And the failure mode is the bad one: the ranker doesn't return a *wrong* answer, it
returns *nothing*, killing the whole cycle. Day 8's fake-gap detector is what started leaving the
empty CSVs behind, so the two interact.

**Fix.** Added `_coerce_ohlcv()` and applied it in both `load_rh_bars()` and `_bars_from()`:
forces numeric dtype, drops unparseable rows. No ranking semantics changed. `rank` returned a full
ordering immediately afterwards.
