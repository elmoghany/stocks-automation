ALLOWED: `Read`/`Write`/`Edit` of repo files; read-only shell (`Get-Date`,
`Get-ChildItem`, `Get-Content`, `git status/log/diff`, `Start-Sleep`,
`Add-Content`); `PushNotification`; `CronList`.

**Diagnosis.** `--permission-mode acceptEdits` auto-approves *edits only* — it
has never granted shell or MCP. Days 8–15 must therefore have been running on a
user-level allowlist (`~/.claude/settings.json`) that is no longer in effect for
this launch. The launcher itself is unchanged in this respect since 2026-08-19
(`git log -p plan/launch_paper_day.ps1` confirms `acceptEdits` throughout), so
the change is environmental, not a regression in the repo.

Note the failure mode's shape: **the liveness signal and the ability to work are
independent.** The day-file skeleton was written, so the launcher's 720 s check,
the 12:00 watchdog and the no-double-launch guard all read this session as
healthy. A session can be perfectly "alive" and completely inert. That is the
same class of hole as Day 14's turn-end death, one layer up.

## Fix applied (needs review + commit — the session cannot commit)

`day-trading/plan/launch_paper_day.ps1` now names the grants on the command
line, where no settings file can lose them:

```powershell
$allowed = "Read,Write,Edit,Glob,Grep,TodoWrite,Bash,PowerShell,Monitor,BashOutput,KillShell,WebFetch,mcp__robinhood-trading"
Start-Process ... -ArgumentList @("-p", $prompt, "--permission-mode", "acceptEdits", "--allowedTools", $allowed)
```

`--dangerously-skip-permissions` was deliberately **not** used. If this CLI
build rejects `--allowedTools`, claude exits fast, no day file appears, and the
existing 720 s check writes `LAUNCH_FAILED_{day}.flag` and clears the scheduler
flag for the backup path — the failure is caught, not silent.

**Recommended second layer (needs the user — the agent is not permitted to write
settings files): put the same grants in `~/.claude/settings.json` `permissions.allow`
so an interactive or differently-launched session is covered too.**

## Lessons

1. **Liveness ≠ capability.** Every watchdog in this campaign keys on the day
   file's existence and mtime. Both can be true while the agent is inert. The
   pre-open checklist needs a **capability probe**: before 07:00, run one
   `python -c "print(1)"`, one `git status`, and one cheap MCP call, and write
   the three results into the day JSON's `ops` block. A missing capability then
   trips the same alarm as a missing session.
2. **Permission grants must live where the launcher can see them.** A user-level
   allowlist is invisible to the repo, unversioned, and silently lost. Anything
   an unattended session depends on belongs on the command line, in the file the
   scheduler runs — which is version-controlled and reviewable.
3. **A headless agent cannot escalate its own permissions, and should not try.**
   Settings files are write-protected precisely so it can't. The correct response
   is to fail loudly, in the places a human already looks (flag file, scheduler
   log, notification), and to leave a reviewable fix behind.
4. **The Day-15 prompt-pointer fix is confirmed good.** The mandate arrived whole
   for the first time in three launches. That defect is closed; this is a new,
   unrelated one.
